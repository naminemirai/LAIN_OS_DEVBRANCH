# LAIN_OS v0 Runtime Implementation Plan

**Goal:** Build a local-first Python 3.11+ runtime that validates ACTION_PROTOCOL requests, authorizes narrow capabilities, executes and verifies them deterministically, and records redacted audit events on Linux/Termux.

**Architecture:** Keep the planner boundary outside the trusted runtime. JSON requests enter a strict parser/validator, capability metadata feeds a policy engine, executors perform narrow operations without `shell=True`, verifiers check postconditions independently, and an append-only JSONL audit log records redacted outcomes. Android adapters are isolated and must return explicit unsupported/limited results when Termux/Android tools are absent.

**Tech Stack:** Python 3.11+ standard library (`dataclasses`, `enum`, `json`, `pathlib`, `hashlib`, `uuid`, `datetime`, `subprocess`, `tempfile`, `shutil`, `tomllib`, `unittest`). No runtime third-party dependencies.

**Spec:** `specs/ACTION_PROTOCOL.md`, `docs/ARCHITECTURE.md`, `docs/SECURITY.md`, plus the approved v0 implementation contract from the 2026-09-29 implementation handoff.

## Global Constraints

- Model output is untrusted input; planner text never grants authority.
- Public protocol exposes only `file.write_text`, `file.copy`, `file.move`, `android.notify`, and `android.open_uri` in v0.
- Unknown capabilities and protocol versions fail closed.
- Filesystem access is limited to explicit configured roots; traversal and symlink escapes are rejected.
- No `shell=True`, no arbitrary shell capability, no Google dependency, no network listener, no AccessibilityService or Shizuku in v0.
- Writes default to no overwrite; UTF-8 text only; file writes are atomic where practical.
- Execution and verification are distinct; Android success is at most `LIMITED` when only command acceptance can be observed.
- Audit is append-only JSONL and recursively redacts secret-like keys.
- Runtime remains testable on ordinary Linux and degrades explicitly when Android tooling is unavailable.

## Review Focus

1. Symlink inside an allowed root that resolves outside it must be rejected before file mutation; covered in Task 2 path-safety tests.
2. A repeated `request_id` must not execute a consequential action twice; covered in Task 4 duplicate-request test.
3. `file.write_text` exceeding configured `max_text_write_bytes` must fail before creating/truncating a file; covered in Task 3 limit test.
4. Android adapter timeouts/nonzero exits must return structured failure without `shell=True`; covered in Task 5 adapter tests using an injected runner.
5. A malformed/corrupt audit line must not be treated as proof a request already executed; covered in Task 4 audit scan test.
